# Ассеты админки

Bootstrap 5 + Bootstrap Icons + свои стили и скрипты, собираются ESBuild + Sass в `dist/`.

```
npm run build        # разово
npm run watch        # пересборка при изменении src/
npm run theme        # экспорт ручек палитры для песочницы → docs/theme-defaults.js
npm run clean        # удалить dist/
```

Из dev-контейнера:

```
docker compose exec node sh -c 'cd /home/node/app/backend/views/assets/media && npm run build'
```

| Что | Откуда | Куда |
|---|---|---|
| CSS | `src/scss/index.scss` | `dist/css/adm.css` |
| JS | `src/js/bootstrap.ts`, `src/js/index.ts` | `dist/js/bootstrap.js`, `dist/js/index.js` |
| Шрифты иконок | `node_modules/bootstrap-icons` | `dist/fonts/` |

Конфигурация сборки — `esbuild.config.js`.

## Палитра: как устроена

Цвета админки **не пишутся руками** — они генерируются из семи базовых цветов и нескольких
чисел. Файлы в `src/scss/imports/` идут слоями, каждый знает только о предыдущем:

```
_theme.scss      ручки: базовые цвета, тон, форма линейки, роли      ← правится руками
_palette.scss    движок: считает линейки, выпускает --adm-<семейство>-<ступень>
_variables.scss  семантика: --adm-btn-primary-bg, --adm-menu-item-color, …
buttons.scss …   компоненты: только var(--adm-*), ни одного hex
```

Проверка чистоты: `rg '#[0-9a-f]{3,8}\b' src/scss --glob '!**/_theme.scss'` должен
возвращать пусто.

### Принцип в четырёх шагах

1. **Из базового цвета берётся только оттенок** (hue в OKLCH). Его светлота и насыщенность
   выбрасываются. Поэтому `#198754` и `#22c55e` в `$hues` дадут одинаковый результат — оттенок
   у них один. Менять базовый цвет имеет смысл, только если нужен другой тон: травянее, розовее.

2. **Ступень 500 у всех семейств получает один тон** — `$tone-lightness` и `$tone-chroma`.
   Отсюда ровный ряд кнопок: раньше при равном «весе» зелёный светился сильнее синего, потому что
   при равной формальной светлоте разные оттенки воспринимаются по-разному. В OKLCH светлота
   перцептивна, и это уравнивается само.

3. **Ступени** строятся от 500: светлее — примесь белого (`tint`), темнее — срез светлоты
   при удержании цвета (`shade`). Итог загоняется в sRGB, иначе тёмные насыщенные тона
   обрезаются по каналу и «залипают» (зелёный уходил в `#154d00`).

4. **Роли.** Компонент не знает hex. Он знает «кнопка в покое — ступень 500». Поменять
   `$btn-rest: 500` на `700` — и все кнопки разом темнеют, сохраняя оттенки и перепады между
   состояниями.

### Закреплённые семейства

`$fixed: ("brand", "neutral")` — эти два берутся **целиком**, как заданы, и общий тон на них
не действует:

- `brand` — фирменный. Шапка, меню и активная страница пагинации не должны перекрашиваться
  от того, что подкрутили тон кнопок.
- `neutral` — фон, границы, текст страницы. Тоже не должны ездить за кнопками, а при высокой
  насыщенности «серый» вообще перестаёт быть серым (при `chroma 0.19` он становился `#5877a5`).

Цвет текста на заливке (белый или тёмный) считается автоматически по светлоте —
`$on-color-threshold`. Вручную не задаётся: жёлтая кнопка получает тёмный текст сама.

### Ручки — что крутить

Всё в `_theme.scss`. По убыванию частоты использования:

| Ручка | Что делает |
|---|---|
| `$tone-lightness`, `$tone-chroma` | Главные. Вся палитра глубже / светлее, приглушённее / сочнее |
| `$btn-rest`, `$btn-hover`, … | Какая ступень за какое состояние. Одно число — все кнопки |
| `$hues` | Оттенки семейств. Только оттенок, светлота hex не важна |
| `$tone-tweaks` | Поправки к тону для отдельных семейств (жёлтый при 0.5 болотный) |
| `$tint-chroma-falloff` | Сколько цвета держат светлые ступени. 1 — чистая пастель, ниже — сочнее |
| `$shade-chroma-falloff` | Спад цвета на тёмных ступенях. 0 — залипание в sRGB |
| `$steps` | Форма линейки: доли белого и срезы светлоты по ступеням |

Типичные задачи:

- **Кнопки слишком яркие** → `$tone-chroma` ниже (0.19 → 0.14).
- **Кнопки слишком светлые/тёмные** → `$tone-lightness`, либо `$btn-rest` на ступень.
- **Один цвет не в тон остальным** → поправка в `$tone-tweaks`, не hex в `$hues`.
- **Фон меню серит** → `$tint-chroma-falloff` ниже (0.8 → 0.6).
- **Нужен новый цвет** → строка в `$hues`, дальше он получает линейку и `-rgb`-триплеты сам.

### Песочница

`docs/palette-knobs.html` — статичная страница, открывается двойным кликом, сервер не нужен.
В ней те же формулы, что в `_palette.scss`: слева ручки в том же порядке, что в `_theme.scss`,
справа линейки, превью кнопок/меню/алертов, таблица контрастов с флагом «сольётся» и готовый
блок для вставки в `_theme.scss`. Настройки запоминаются в браузере.

Она привязана к исходникам через `npm run theme` (`export-theme.js`): скрипт вытаскивает все
переменные `_theme.scss` (через `meta.module-variables`, поэтому новая ручка попадает в экспорт
сама) и ступени, посчитанные Sass, в `docs/theme-defaults.js`. Песочница подключает его
`<script src>` — в отличие от `fetch` это работает и по `file://`. Пока ручки не тронуты, она
показывает hex ровно как в `adm.css`; после кручения — свой расчёт, который может разойтись
с Sass на 1–2 единицы в hex из-за иного gamut-приведения (на глаз не видно). Кнопка
«Сбросить к _theme.scss» возвращает к экспортированным значениям.

Порядок: `npm run theme` → покрутил → «Скопировать» → вставил в `_theme.scss` →
`npm run build` → `npm run theme` (чтобы песочница снова показывала точные значения).

Без `theme-defaults.js` (не запускали `npm run theme`) страница работает на встроенных
умолчаниях и говорит об этом в шапке.

### Как использовать в стилях

```scss
// в _variables.scss — семантика через роли
--adm-btn-primary-bg: #{p.step("primary", th.$btn-rest)};        // var(--adm-primary-500)
--adm-sidebar-shadow: 6px 0 8px 0 #{p.step-rgba("neutral", 900, 0.1)};

// в компонентах — только семантические переменные
.btn-primary { background-color: var(--adm-btn-primary-bg); }
```

Прямые ссылки на ступени (`var(--adm-primary-500)`) в компонентах не писать — тогда роль
перестанет управлять этим местом.
